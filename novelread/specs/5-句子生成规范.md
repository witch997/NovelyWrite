# 句子生成规范

> 网文分析系统 · 句子层 ｜ v4.0
> 定位：句子层标注操作规程，独立成文自《句子层定义规范》v2.0。
> 流程定位：《语料分析》skill 第二步（与分镜标注一次 LLM 往返）——产出**句子标注 JSON（中间件）**，供分镜标注与 S# 取证。
> 依赖：《句子层定义规范》（§3 判断规范、§6 归属）；**格式契约以《JSON数据格式参考》§2 为唯一标准**。
> 变更：v1.0 → v2.0 删去"单元"，统一使用**句子**（短句/句从为句子的两种结构类型）→ v2.1 对齐《拆书》skill：句子标注文档定位为中间件 → v3.0 产出格式改为 JSON（`dsh/sentence-card/v1`）→ **v4.0 轻标注：删除句子层的类型（type）与功能（funcs）标注——类型/功能信息由分镜层承载（分镜 type/funcs 为分镜级直接判定）；句子层只保留结构切分（struct）与原文**。

## 1. 标注目标

按判断规范将章节文本切分为**句子序列**（短句/句从结构类），产出**句子标注 JSON**（中间件，句子结构 + 原文），供分镜标注与 S# 取证。

**轻标注原则（已定稿）**：句子层**不标注类型与功能**——`type`/`funcs` 字段已从 `dsh/sentence-card/v1` 删除。类型/功能由分镜层判定（分镜级粒度更合理）。

**唯一产出格式**：`dsh/sentence-card/v1`（字段定义、约定、示例见《JSON数据格式参考》§2，本规范不再重复定义格式，仅引用）。

## 1.1 输入与输出

| | 内容 | 路径 |
|---|---|---|
| **输入** | 语料分章文件（单章原文） | `store/<语料名>project/语料分章/第XXXX章_标题.txt` |
| **输出** | 句子标注 JSON（中间件） | `store/<语料名>project/句子标注/json/第XXXX章.json`（`dsh/sentence-card/v1`） |
| **消费方** | 分镜层（切镜输入） | — |

- 输入边界：章边界由语料分章给定，只记录不判定
- 输出流向：`sentence JSON → 分镜层`

## 2. 标注流程（单步：切分）

**句子切分**——按判断规范（定义规范 §3）将章节文本切分为句子序列：片段切分（§3.1）→ 聚合/断开裁决（§3.2/3.3），判定每个句子的结构类（短句 / 句从）。

> 原"第二步：类型与功能标注"已删除（轻标注：类型/功能由分镜层承载）。

产出：句子标注 JSON（§3 格式契约）。

## 3. 标注格式（JSON 唯一）

**格式契约**：`dsh/sentence-card/v1`（《JSON数据格式参考》§2）。核心字段：

| 字段 | 说明 |
|---|---|
| `schema` | `dsh/sentence-card/v1` |
| `chapter` | {number, title, range} |
| `source` | **源语料分章文件路径**（JSON 直接产出，无 .md 中间产物） |
| `sentences[]` | 句子数组（按 seq 升序） |
| `sentences[].id` | S#（章内全局连续） |
| `sentences[].seq` | 章内序号 |
| `sentences[].struct` | 短句 / 句从 |
| `sentences[].text` | 原文（逐字保留） |
| `sentences[].shotId` | 归属分镜（拆书第二步回填；未回填为 null） |
| `sentences[].note` | 仅承载存疑说明（诊断信号不在此字段） |

**字段约定**（见《JSON数据格式参考》§2）：
- **轻标注**：无 `type`/`funcs` 字段（类型/功能由分镜层承载）
- 片段不建模：句从只存聚合后的整句 `text`，不存片段级结构
- note 语义收窄：仅存疑说明

## 4. 标注规则

- **无遗漏**：原文每个字符必须归属且仅归属一个句子
- **一致性**：同一标注者对同一文本重复标注，切分边界须稳定一致
- **继承显式化**：句子不携带时空/视角/焦点（沿所属分镜继承），不重复声明
- **存疑透明**：无法按判据唯一确定的样本，先按 §6 诊断信号辅助裁定；仍无法定论的标记疑点并写入 `note`，进入边界问题清单
- **归属校验**：每个句子归属且仅归属一个分镜；句从内片段不独立归属（`shotId` 拆书第二步回填前为 null）

## 5. 标注产物

- **句子标注 JSON**（中间件）：`store/<语料名>project/句子标注/json/第XXXX章.json`，格式 `dsh/sentence-card/v1`；供分镜标注（拆书第二步）与 S# 取证
- **边界问题清单**：存疑样本（`note` 字段 + 清单），作为判断规范修订的输入

## 6. 存疑与诊断

- 存疑样本写入 `note` 字段并写明原因，进入边界问题清单
- 句子层诊断信号（开放注册，低优先级兜底，机制同《分镜生成规范》§6；诊断结果**不写入句子 JSON**，由校验/诊断层单独产出）：

| # | 触发条件 | 处理建议 |
|---|---|---|
| 1 | 句从型句子含 >6 片段 | 复核聚合是否过宽，疑似应断开 |
| 2 | 短句型句子缺主语且上下文无主体 | 复核归属，疑似应为句从或漏标 |
| 3 | 信息不足片段未聚合为句从 | 复核判断规范，应聚合 |
| 4 | 句子超长（>80字） | 复核是否可拆为多句 |

## 附：格式变更对照（v3.0 → v4.0）

| | v3.0（已废弃） | v4.0（唯一） |
|---|---|---|
| 字段 | struct/type/funcs/text/shotId | **struct/text/shotId**（type/funcs 已删） |
| 标注内容 | 切分 + 类型六型 + 功能五型 | **仅切分（struct）** |
| 类型/功能信息 | 句子层持有 | **分镜层承载**（分镜级直接判定） |
| 标注负担 | 高（每句判类型+功能） | **低（只判切分）** |
