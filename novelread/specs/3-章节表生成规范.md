# 章节表生成规范

> 网文分析系统 · 章节层 ｜ v2.6
> 依据：《章节层定义规范》v2.1
> 流程定位：《语料分析》skill 第三步——产出**章节表（中间件）**。
> 变更：v2.0 层次简化，表结构仅保留核心列——**章节功能**与**章节简述** → v2.1 简述要求放宽：删除模板，句数不限，字数 ≤400 → v2.2 术语同步：删去"单元"，句子层标注改称"句子标注" → v2.3 对齐《全书分析》skill：章节表定位为中间件 → v2.4 章节层输出改为两个 JSON 文件（章节标注 + 章节表）；新增 mainlineProgress → v2.5 轻标注：删除无来源字段 entities/foreshadowing/foreshadowingLifecycle（分镜层不再标注实体）；钩子改称悬念（hooks→suspense、endingHook→endingSuspense）→ **v2.6 删除末镜悬念校验（endingSuspense/suspenseRate）——悬念判定不再作为章节级必需属性**。

## 1. 目的

按章生成章节登记表，核心输出**章节功能**与**章节简述**；简述开放给大事件层进行上层分析（大事件抽取、主线追踪、主线判定）。

## 1.1 输入与输出

| | 内容 | 路径 |
|---|---|---|
| **输入** | 分镜标注 JSON（同章，分镜序列 + 类型/语法/功能） | `store/<语料名>project/分镜标注/json/第XXXX章.json` |
| **输出①** | 章节标注 JSON（单章事实） | `store/<语料名>project/章节/第XXXX章.json`（`dsh/chapter-annotation/v1`） |
| **输出②** | 章节表 JSON（全卷聚合视图） | `store/<语料名>project/章节/章节表.json`（`dsh/chapter-table/v1`，带 `derivedFrom` 版本戳） |
| **消费方** | 大事件层（读章节表 JSON 的 summary 抽动机） | — |

- 输入边界：分镜 JSON 的 `sentenceRange`/`funcs[0]`（主导功能）为章节功能判定依据
- 输出流向：`chapter JSON + chapter-table JSON → 大事件层`

## 1.2 JSON 格式契约（自含，本规范唯一格式依据）

### 章节标注 `dsh/chapter-annotation/v1`（单章事实）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema | string | ✅ | `dsh/chapter-annotation/v1` |
| chapter | object | ✅ | {number, title, textRange} |
| function | enum | ✅ | chapterFunc（开端/推进/铺垫/爆发/转折/收束章节/过渡） |
| summary | string | ✅ | 章节简述 ≤400字 |
| mainlineProgress | array | ✅ | 本章主线进展 [{entity, state, evidence}] |
| stats | object | ✅ | 派生统计（sentenceCount/shotCount/shotTypeDist/funcDist/shortSentenceRate/sentenceClusterRate） |
| suspense | array | ✅ | 章内悬念分镜 [{shot, label, sentenceRange}] |
| source | string | ✅ | 源分镜标注 JSON 路径 |

> 注：`entities`/`foreshadowing` 已删除（轻标注）——分镜层不再标注实体，实体信息由句子层实体库派生；伏笔由大事件层生命周期承担。

### 章节表 `dsh/chapter-table/v1`（全卷聚合）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema | string | ✅ | `dsh/chapter-table/v1` |
| volume | object | ✅ | {name, chapterRange} |
| chapters | array | ✅ | 全卷章节条目 [{number, title, function, statsRef}]——summary 不落副本（唯一合法源在章节标注），消费方按 statsRef join |
| mainlineProgress | array | ✅ | 主线状态轨迹 [{chapter, entity, state}] |
| stats | object | ✅ | 卷级统计（chapterCount/avgShotsPerChapter） |
| derivedFrom | object | ✅ | 源数据版本戳 |
| source | string | ✅ | 源章节标注目录 |

> 注：`foreshadowingLifecycle` 已删除（轻标注）——伏笔生命周期由大事件层 `lifecycle` 承担。

## 2. 表结构

| 章号 | 文本范围 | 章节功能 | 章节简述 |

## 3. 章节功能

- **定义**：本章在叙事中的作用
- **初始集**：开端 / 推进 / 铺垫 / 爆发 / 转折 / 收束章节 / 过渡
- **判定**：由分镜功能聚合（《分镜层定义规范》§7.2 映射）归纳，或由章节简述直接归纳；不做价值判断（不使用"注水"概念）

## 4. 章节简述（最重要）

**用途**：开放给大事件层进行分析——本输出是章节层最重要的产物。

- **覆盖要素**：核心情节、主线目标进展、关键事件；优先体现含{悬念/反转/爆发/设置动机}的分镜信息
- **要求**：陈述句、客观描述、不做价值评价；句数不限；字数 ≤400 字

## 4.1 主线目标进展（结构化字段）

章节简述中的"主线目标进展"要素**同时以结构化字段承载**（供程序化追踪与主线判定）：

- **章节标注**（`dsh/chapter-annotation/v1`）：`mainlineProgress[]` 字段，记录本章涉及的主线进展
  - 元素：`{entity: 主线实体, state: 主线状态, evidence: 分镜/简述依据}`
  - `state` 取 mainlineState 枚举（主线启动/推进/受阻/达成/更换）
  - `evidence` 指向支撑的分镜或简述位置，可回源
- **章节表**（`dsh/chapter-table/v1`）：卷级 `mainlineProgress[]`，由各章章节标注按章聚合，构成主线状态轨迹
  - 元素：`{chapter: 章号, entity: 主线实体, state: mainlineState}`
- **判定来源**：从分镜功能聚合（§7.2 映射）+ 章节简述归纳；多章连续同实体同目标即主线候选（大事件层判定规则）

## 5. 生成流程

1. **边界登记**：章号、文本范围（边界给定，只记录）
2. **拆书**：引用《语料分析》skill 第二步产出的分镜标注 JSON（`store/<语料名>project/分镜标注/json/第XXXX章.json`，供章节功能聚合）
3. **判定章节功能**（§3）
4. **撰写章节简述**（§4）
5. **产物归档**（§6）

## 6. 生成产物

- **章节标注**（单章）：`store/<语料名>project/章节/第XXXX章.json`（格式 `dsh/chapter-annotation/v1`），按本规范逐章生成
- **章节表**（全卷聚合）：`store/<语料名>project/章节/章节表.json`（格式 `dsh/chapter-table/v1`），由各章章节标注聚合生成，带 `derivedFrom` 版本戳
- 更新机制：每章完成标注后回填章节标注，并级联更新章节表（增量重算受影响部分）
- 当前进度：第1-60章已拆解；章节 JSON 化待批量转换
