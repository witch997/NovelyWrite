# 卷纲生成规范

> 网文分析系统 · 单卷层 ｜ v3.0
> 对应层：单卷层（`novelread/specs/`）
> 依据：《单卷层定义规范》v3.2（最终输出：简纲）
> 流程定位：《语料分析》skill 第五步——产出**卷纲（最终产出）**。
> 定位：单卷层的操作规程——读取章节标注 summary，生成**目标驱动卷纲**（目标的跨章判断）。
> 变更：v1.1 阶段序列/动机序列结构 → v2.0 卷纲改为事件驱动结构（JSON：`dsh/volume-card/v1`）→ **v3.0 卷纲改为目标驱动结构：删除 eventStructure[]/mainline，改为 targets[]（目标跨章判断）；与 event.json 彻底正交（只吃 summary，不读 event.json）；isMain 由宿主脚本派生**。

## 1. 目的

读取**全部已标注章的 summary**，生成**目标驱动卷纲**：归纳本卷要达成的目标（targets[]），判断每个目标的跨章推进状态，并提供风险诊断（diagnostics）。

**职责边界**：卷纲只回答「**要达成什么、离达成多远**」（目标跨章判断）；「**发生了什么、进行到哪**」（事件跨章判断）归大事件层 event.json。两者**彻底正交**：卷纲不引用任何事件实体名，事件变化不触发卷纲重算。

## 2. 输入

- **章节标注**：`store/<语料名>project/章节/第XXXX章.json`（各章 summary——**唯一语义输入**；与 event.json 平级，互不派生）

## 3. 卷纲结构

### 3.1 目标驱动结构（JSON，机器可读）

```
卷纲 JSON = 卷名/章节范围
          + 单卷目标（goal）
          + 目标跨章判断（targets[]，核心）：
              目标1（state）├─ 证据章 evidenceChapters[]
                           └─ note
              目标2（state）…
          + 风险诊断（diagnostics[]）
```

**目标判定规则**：
- **target**：卷级意图（如「宝黛爱情确立与深化」）。**不得引用事件名**——判断标准：删掉所有事件名后，描述仍成立。
- **state**：目标语义词表（见下），与事件的 悬置/已回收 词表区分。
- **evidenceChapters**：推进该目标的章号数组，LLM 从 summary 直接判定（不依赖 event.json）。
- **note**：叙述性说明（可提及事件作佐证，但结构化字段不引用事件）。
- **isMain**：由宿主脚本派生（按 evidenceChapters.length 降序，命中最多者为唯一主目标 `isMain: true`，其余不写），**LLM 不输出**。

### 3.1.1 JSON 格式契约（自含，本规范唯一格式依据）

**卷纲 JSON `dsh/volume-card/v1`：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema | string | ✅ | `dsh/volume-card/v1` |
| volume | object | ✅ | {name, chapterRange} |
| goal | string | ✅ | 单卷总目标 |
| targets | array | ✅ | 目标跨章判断（3-6 条，只列卷级意图；单章内小目标不列） |
| diagnostics | array | | 诊断备注 [{level:"⚠", issue}] |
| derivedFrom | string | ✅ | 源数据版本戳（指向章节——与 event.json 平级） |

**targets[] 元素：** `{target: 目标名（卷级意图，不得引用事件名）, state: 确立/推进/达成/搁置/失败, evidenceChapters: int[]（推进该目标的章号）, note: 叙述性说明, isMain?: 仅主目标写 true}`

**targetState 词表（目标语义，区别于 lifecycleState）：**

| state | 含义 | 典型场景 |
|---|---|---|
| 确立 | 目标刚被立起，尚未实质展开 | 卷首/目标首次被明确提出（≤2 章） |
| 推进 | 正在实质推进 | 主体阶段 |
| 达成 | 目标达成 | 卷末收束 |
| 搁置 | 暂停，可能重启 | 支线暂歇 |
| 失败 | 明确失败 | 目标破灭 |

**已废弃（不得输出）**：`eventStructure[]`（事件跨章判断已归 event.json）、`mainline{result,state,evidence}`（已并入 targets）。

## 4. 要求

- 陈述句、客观、无价值评价
- 以机器可读为唯一标准（JSON 为单一事实源，不设篇幅上限）
- 与《单卷层定义规范》§4 一致
- **正交约束**：调用②只吃全部 summary，不读 event.json；targets 结构化字段不引用任何事件实体名

## 5. 生成流程

1. **读 summary**：从全部已标注章章节标注取 summary（唯一输入）
2. **判目标**：LLM 归纳卷级目标 targets[]（target/state/evidenceChapters/note），state 取目标五态
3. **判诊断**：goal / diagnostics 语义判定
4. **派生 isMain**（宿主脚本）：按 evidenceChapters.length 降序排序 targets，命中最多者为唯一主目标（`isMain: true`，其余不写）
5. **生成 JSON**：`volume.json`（目标驱动结构，`dsh/volume-card/v1`）
6. **产物归档**（§6）

## 6. 生成产物

- **卷纲 JSON**（机器可读）：`store/<语料名>project/卷纲/volume.json`（格式 `dsh/volume-card/v1`，目标驱动结构）
- store 内不生成人类可读文件；拆书报告由专门的拆书功能读取卷纲 JSON 后另行生成
- 更新机制（增量）：见《语料分析-SKILL》【聚合层·增量更新】——新增章单独聚合为 `卷纲/volumetemp-<ts>.json`，合并判定后并入正式文件，event.json 变化**不**触发卷纲重算
