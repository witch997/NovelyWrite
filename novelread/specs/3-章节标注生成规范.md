> 网文分析系统 · 章节层 ｜ v2.9
> 依据：《章节层定义规范》v2.1
> 流程定位：《语料分析》skill 第三步——产出**章节标注（单章事实）**。
> 变更：v2.0 层次简化，表结构仅保留核心列——**章节功能**与**章节简述** → v2.1 简述要求放宽：删除模板，句数不限，字数 ≤400 → v2.2 术语同步：删去"单元"，句子层标注改称"句子标注" → v2.3 对齐《全书分析》skill：章节表定位为中间件 → v2.4 章节层输出改为两个 JSON 文件（章节标注 + 章节表）；新增 mainlineProgress → v2.5 轻标注：删除无来源字段 entities/foreshadowing/foreshadowingLifecycle（分镜层不再标注实体）；钩子改称悬念（hooks→suspense、endingHook→endingSuspense）→ v2.6 删除末镜悬念校验（endingSuspense/suspenseRate）——悬念判定不再作为章节级必需属性 → v2.7（2026-09-04）聚合层语义删除：summary 消费方由大事件层改为报告 tip 按需搜证 → v2.8（2026-09-04）删除 mainlineProgress：跨章主线判定随聚合层删除、字段无消费方（schema 标识保持 v1，读取方无引用，无需升版）→ **v2.9（2026-09-04）删除章节表契约：章节表（chapter-table）退化为纯投影亦无消费方（报告 tip 直接读章节标注 summary），整体移除；本规范随之更名为"章节标注生成规范"，只承载章节标注契约**。

## 1. 目的

按章生成**章节标注**，核心输出**章节功能**与**章节简述**；简述是跨章语义搜证的唯一权威输入（供报告 tip 的 LLM 按需搜证，见下）。

## 1.1 输入与输出

| | 内容 | 路径 |
|---|---|---|
| **输入** | 分镜标注 JSON（同章，分镜序列 + 类型/语法/功能） | `store/<语料名>project/分镜标注/json/第XXXX章.json` |
| **输出** | 章节标注 JSON（单章事实） | `store/<语料名>project/章节/第XXXX章.json`（`dsh/chapter-annotation/v1`） |
| **消费方** | 确定性聚合（清单恢复 / 缺章报告 / 终检，读规定字段）；报告 tip（LLM 读 summary 按需搜证，跨章语义在此产生）；章节树索引（扫 章节/ 目录枚举章节） | — |

- 输入边界：分镜 JSON 的 `sentenceRange`/`funcs[0]`（主导功能）为章节功能判定依据
- 输出流向：`章节标注 JSON → 确定性聚合（清单/缺章/头文档）`；summary 供报告 tip 搜证、供章节树节点投影

## 1.2 JSON 格式契约（自含，本规范唯一格式依据）

### 章节标注 `dsh/chapter-annotation/v1`（单章事实）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema | string | ✅ | `dsh/chapter-annotation/v1` |
| chapter | object | ✅ | {number, title, textRange} |
| function | enum | ✅ | chapterFunc（开端/推进/铺垫/爆发/转折/收束章节/过渡） |
| summary | string | ✅ | 章节简述 ≤400字 |
| stats | object | ✅ | 派生统计（sentenceCount/shotCount/shotTypeDist/funcDist/shortSentenceRate/sentenceClusterRate）——宿主脚本生成，LLM 不输出 |
| suspense | array | ✅ | 章内悬念分镜 [{shot, label, sentenceRange}]——宿主脚本生成，LLM 不输出 |
| source | string | ✅ | 源分镜标注 JSON 路径 |

> 注：`mainlineProgress` 已删除（2026-09-04，见 v2.8 变更）；`entities`/`foreshadowing` 已删除（轻标注）——分镜层不再标注实体，实体信息由句子层实体库派生；伏笔跨章语义随聚合层删除（2026-09-04）不再由建库承担，报告 tip 按需搜证。
>
> 注：原「章节表 `dsh/chapter-table/v1`（全卷聚合）」契约已删除（2026-09-04，见 v2.9 变更）——`章节/章节表.json` 不再生成，卷级视图无消费方；章号/标题/function/summary 一律以各章标注为唯一事实源，章节树等消费方扫 `章节/第NNNN章.json` 枚举。

## 2. 输出字段

| 章号 | 文本范围 | 章节功能 | 章节简述 |

## 3. 章节功能

- **定义**：本章在叙事中的作用
- **初始集**：开端 / 推进 / 铺垫 / 爆发 / 转折 / 收束章节 / 过渡
- **判定**：由分镜功能聚合（《分镜层定义规范》§7.2 映射）归纳，或由章节简述直接归纳；不做价值判断（不使用"注水"概念）

## 4. 章节简述（最重要）

**用途**：跨章语义搜证的唯一权威输入——报告 tip / 全书梗概只读 summary 做语义判定，不读句子/分镜/原文；本输出是章节层最重要的产物。

- **覆盖要素**：核心情节、主线目标进展、关键事件；优先体现含{悬念/反转/爆发/设置动机}的分镜信息
- **要求**：陈述句、客观描述、不做价值评价；句数不限；字数 ≤400 字

## 4.1 （已删除）主线目标进展结构化字段

> 2026-09-04（v2.8）：原 `mainlineProgress` 结构化字段（章节标注 `mainlineProgress[]` + 章节表卷级主线轨迹）已**整体删除**——其用途是"供程序化追踪与主线判定"，但跨章语义判定已随聚合层删除，字段无消费方。需要主线/目标/事件脉络等跨章语义时，由报告 tip 的 LLM 从各章 summary 按需搜证，不落建库产物（判定规则见下，报告 tip 专用，不落 store）。
> 判定来源（保留供报告 tip 参考）：从分镜功能聚合 + 章节简述归纳；多章连续同实体同目标即主线候选。

## 5. 生成流程

1. **边界登记**：章号、文本范围（边界给定，只记录）
2. **拆书**：引用《语料分析》skill 第二步产出的分镜标注 JSON（`store/<语料名>project/分镜标注/json/第XXXX章.json`，供章节功能聚合）
3. **判定章节功能**（§3）
4. **撰写章节简述**（§4）
5. **产物归档**（§6）

## 6. 生成产物

- **章节标注**（单章）：`store/<语料名>project/章节/第XXXX章.json`（格式 `dsh/chapter-annotation/v1`），按本规范逐章生成；`stats`/`suspense` 由宿主脚本派生后回填
- 更新机制：每章完成标注后由宿主派生 stats/suspense 回填；批末确定性聚合（清单恢复 / 缺章报告 / 终检 / 头文档 / 索引）只读各章标注的规定字段，改动/删除章由重算自然覆盖，无增量协议、无卷级聚合文件
