# 大事件生成规范

> 网文分析系统 · 大事件层 ｜ v4.0
> 定位：大事件层标注操作规程。**按章事件已删除**（v3.0）——大事件信息直接由主文件承载，聚合层从全部章节标注的 summary 一次性判定事件生命周期。
> 流程定位：《语料分析》skill 聚合层阶段二（语义判定调用①）——产出**大事件主文件**（`dsh/event-card/v1`）。
> 依赖：《章节表生成规范》（章节标注，读 summary）。
> 格式契约：**以《JSON数据格式参考》§5 为唯一标准**（`dsh/event-card/v1`）。
> 变更：v1.2 对齐《全书分析》skill → v2.0 输入改为章节表 JSON（全卷），输出为事件 JSON + 生命周期 + 主线判定 → v2.1 输出收敛为方案 B：主文件（event.json）+ 按章事件 → v2.3 轻标注：删除动机的 S# 句子证据与来源分类 → v3.0 删除按章事件：只保留主文件 event.json → **v4.0 事件跨章判断收敛：lifecycle[] 每项加 note；删除 mainline[]（主线判定并入卷纲 targets）与 chapterIndex（与章节表.chapters[] 重复）；lifecycle 条数不限**。

## 1. 标注目标

输入**全部章节标注的 summary**（`dsh/chapter-annotation/v1`，逐章），从 summary 抽取事件内容，用**状态机跨章判断事件生命周期**，生成**大事件主文件**（`dsh/event-card/v1`），供下游查询/检索层消费（事件跨章判断的唯一权威源）。

**输入**：全部章节标注（读各章 `summary`）
**输出**：主文件 `store/<语料名>project/大事件/event.json`（全卷聚合：事件生命周期状态机）

> 按章事件文件（`大事件/event/第XXXX章.json`）**已删除**——不再逐章生成事件中间件；聚合层直接从全部 summary 判定（事实层只产出 句子/分镜/章节标注 三文件）。

## 2. 标注流程（三步，聚合层一次性）

1. **读全部章节标注**：逐章取 `summary`（≤400 字，覆盖核心情节/主线进展/关键事件）
2. **抽事件（跨章）**：从各章 summary 归纳具名事件（含跨章延续），**条数不限**——按语料实际识别出多少就列多少
3. **状态机跨章判断**：对每个事件回溯前章登记生命周期（事件开启/持续/结束），每项写 note（≤60 字）

## 3. 标注格式（JSON 唯一）

**格式契约**：`dsh/event-card/v1`（《JSON数据格式参考》§5）。核心字段：

| 字段 | 说明 |
|---|---|
| `schema` | `dsh/event-card/v1` |
| `volume` | {name, chapterRange} |
| `lifecycle[]` | 跨章生命周期 `{entity, 开始章:int, 持续章:int[], 结束章:int|null, state, note}`；**条数不限** |
| `derivedFrom` | 版本戳（**宿主脚本生成**） |

- **lifecycleState 两种**：`悬置` / `已回收`
- **note（必填）**：≤60 字叙述性说明（事件性质/关键节点/成因，客观陈述）
- `结束章` 为 int 或 null（null = 未了结，不得填字符串）
- **已废弃（不得输出）**：`mainline[]`（主线/目标判定已并入卷纲 targets[]）、`chapterIndex`（与章节表.chapters[] 重复；消费方要章信息 join 章节表）

## 4. 标注规则

- **事件内容**：以 summary 事实为据，客观陈述；事件 = 跨章叙事线（同 entity 合并持续章）
- **生命周期状态机**：同 entity → 更新 持续章[]/结束章/state；新 entity → 追加（开始章=首次出现章号）；未出现条目不保留
- **note**：每项必带，叙述事件性质/关键节点/成因，≤60 字
- **职责边界**：本层只做事件跨章判断（lifecycle）；目标跨章判断（targets）归单卷层卷纲，两文件彻底正交（互不引用）

## 5. 标注产物

- **主文件**（全卷聚合）：`store/<语料名>project/大事件/event.json`，格式 `dsh/event-card/v1`；含 `lifecycle[]`（含 note）+ `derivedFrom`（脚本生成）
- **确定性字段**：`volume.chapterRange` / `derivedFrom` 由宿主脚本强制覆盖，LLM 只输出语义字段（lifecycle[]）
- **废弃字段兜底**：宿主脚本落盘前删除 mainline/chapterIndex（防 LLM 残留）

**职责边界**：事件跨章判断（lifecycle）由本层（聚合层调用①）输出；目标跨章判断（targets）由单卷层调用②输出——两者平行投影同一批 summary，互不派生。

## 6. 存疑与诊断

- 存疑样本进入聚合层语义判定的 diagnostics（不写入生命周期 JSON 的 note，由校验/诊断层单独产出）
- 大事件层诊断信号（开放注册，低优先级兜底）：

| # | 触发条件 | 处理建议 |
|---|---|---|
| 1 | 跨章事件悬空：事件开启后长期未结束/未回收 | 复核生命周期状态机 |
| 2 | 事件 note 缺失或超长 | 复核调用①契约（note 必填 ≤60 字） |
